## 2. Rendering

**Mechanism: a mix.**
- **Compute (main path).** All node and buffer textures are made by GLSL 450 compute shaders on one **local RenderingDevice** (`addons/material_maker/engine/multi_renderer.gd:166-167`, created on a dedicated Thread `:172-178`).
  - Dispatch: `engine/pipeline/compute_shader.gd:119-165`.
  - Sources are `.tres` text with `#version 450`, compiled at runtime via `shader_compile_spirv_from_source` (`engine/pipeline/pipeline.gd:103-124`).
- **Raster on the same RD.** `engine/pipeline/rendering_pipeline.gd:34-106`, used by mesh map baking (`map_generator.gd:119-157`) and the painter.
- **Previews in the main renderer.**
  - 2D: a `canvas_item` ShaderMaterial (`material_maker/panels/preview_2d/preview_2d.gd:22-45`, shader from `gen_base.gd:501-523`).
  - 3D: a spatial ShaderMaterial (`addons/material_maker/engine/nodes/gen_material.gd:192-210`) in a SubViewport (`material_maker/panels/preview_3d/preview_3d.gd`).
  - Buffer and channel textures are read back GPU→CPU→GPU (`engine/pipeline/texture.gd:58-82`, `texture_get_data`).
- **Legacy SubViewport, 8-bit.** `engine/renderer.gd:68-111`; HDR is commented out at `:84-89`. Used for text nodes and animation export.
- **Shader generation.** The same node snippets are emitted both as Godot shading language and as raw GLSL compute (`compute_shader.gd:80-109`, templates `buffer_compute.tres`, `iterate_buffer_compute.tres`). Preprocessing: `engine/preprocessor.gd`.

**Formats.**
- One table, `pipeline.gd:61-72`: R16F, RGBA16F, R32F, RGBA32F, D32.
- Default r16f/rgba16f storage images; the "32 bits" option gives r32f/rgba32f (`compute_shader.gd:104-106`).
- Mesh maps, painter and TAA hard-code RGBA32F (`map_generator.gd:126`, `painter.gd:175`, `export_taa.gd:41`).
- Usage bits are STORAGE|SAMPLING|CAN_UPDATE|CAN_COPY_FROM (`pipeline.gd:404-411`).
- All samplers are LINEAR, including 32F (`pipeline.gd:427-433`).

**Risks on Vulkan Mobile / Adreno (8 Elite):**

| # | Risk | Where | D | B |
|---|---|---|---|---|
| R1 | Compatibility renderer → `create_local_rendering_device()` = null → nothing renders; no guard | `multi_renderer.gd:167` | low | yes if GLES3 chosen. **Must stay Vulkan (ADR 0004)** |
| R2 | `r16f` storage image needs `shaderStorageImageExtendedFormats` (default greyscale format) | `compute_shader.gd:104`, `pipeline.gd:67` | low | yes if unsupported — verify on device (P2) |
| R3 | LINEAR filtering of R32F/RGBA32F is optional in Vulkan | `pipeline.gd:427-433` | med | maybe (32-bit buffers; baking/painting are out of scope) |
| R4 | Per-chunk `submit()+sync()`, per-chunk pipeline creation, full readback each update → stalls/thermal | `compute_shader.gd:130,158`, `texture.gd:60` | med | no (performance, P4) |
| R5 | Long dispatches at 2048–4096² → GPU timeout / device lost | `compute_shader.gd:274-276` | med | possibly, heavy graphs |
| R6 | Imported VRAM-compressed images (ETC2/ASTC) not handled in upload; DXT→BC unsupported on Adreno | `texture.gd:84-110` | low | yes for image nodes using imported resources |
| R7 | Runtime SPIR-V compile needs glslang in the template (stock: present) | `pipeline.gd:108` | low | no with stock templates |
| R8 | Render thread busy-polls `try_lock` each frame; long syncs → ANR risk | `multi_renderer.gd:137-162` | med | no |

## Top-5 risks
1. **R2/R1 — compute pipeline on Adreno (Vulkan Mobile).** Everything renders through a local RenderingDevice with r16f/rgba16f storage images. If the format or local RD fails, nothing works. P2 answers this.
2. **Exe-dir paths** (`paths.gd:12`, `add_node_popup.gd:281`): a crash in the add-node popup, plus broken image/env/alias paths. Cheap to fix, but a hard blocker.
3. **Window model**: `embed_subwindows=false`, undock, 1x1 transparent boot window, size/DPI restore. This may give a black or tiny window or broken popups on Android.
4. **Right-click-only actions** (add node, node menu, library, point delete): core graph editing is impossible without a long-press shim.
5. **Files**: FileDialog with `ACCESS_FILESYSTEM` + deprecated storage permissions; SAF `content://` from native dialogs. Examples are not exported at all.
